# Runecaster 后续计划（Roadmap）

> 基于 2026-07-06 三视角评审（策划 / 美术 / 工程），全文见 `docs/reviews/`。
> 状态基线：`cargo test -p rune_core` 32/32 通过；clippy 仅 1 个测试文件风格 warning。

## 总体判断（三方共识）

- **基建罕见地好**：rune_core 纯逻辑秒级全测、逻辑/渲染分离干净、FX 粒子层已达小品级——这是值得押注的底子。
- **核心卖点"拼词施法"成立一半**：表达链（拼词→预览→施放→涌现组合）是通的，但被两个结构性问题拆台：
  1. 同符文可在词内无限重复 × 威力二次方增长 → "堆 Fire"碾压一切，16 个符文 5 个数值死刑；
  2. 无时间压力 + 怪物视野外休眠 → 挂机回蓝零成本，法力经济名存实亡。
- **表现层"骨架强、反馈缺"**：粒子/震屏/滑动到位；受击闪白、近战 lunge、血条、怪物剪影缺失。
- **完成度定位**：pre-alpha 垂直切片。距离"好玩的小品"欠的是设计翻修 + 战斗反馈，不是重写。

## 关键排序逻辑

1. **测试先行于翻修**——Phase 1 会动所有数值，先建回放/边界测试安全网（Phase 0）。
2. **数值回归测试放在重平衡之后**——先锁旧值等于白写。
3. **main.rs 拆分先于 juice/UI 工作**——否则所有改动都挤在 1370 行单文件里互相冲突。
4. **怪物美术与新怪种合并成一个包**——避免给旧圆球画完皮又为新怪重画一轮。
