# Runecaster 美术与表现力评审（游戏美术视角）

> 评审日期：2026-07-06 ｜ 评审执行：opus-4.8 subagent（资深像素风/游戏 juice 视觉总监角色）
> 范围：main.rs 全部表现层代码（px_* 贴图 / elem_burst / spawn_cast_fx / UI / animate / 震屏）+ README
> ⚠️ 限制：未编译运行（Bevy 编译被禁止），全部结论由颜色值/尺寸/粒子参数推演，【需截图】项待真机验证

## 总体判断

**当前表现力水平**：一个**"粒子系统惊艳、静态美术占位"的原型**。FX/粒子层（`elem_burst` + `spawn_cast_fx` + trauma 震屏 + 投射物拖尾）已经达到"有 juice 的小品级"水准，是全项目最强、最像"成品"的部分；但**角色 sprite（尤其怪物）、瓦片、UI 排版仍停留在占位阶段**。整体色板方向其实是成立的——冷调蓝灰地牢 + 珠宝色元素高光，这是一个真实、可读的美术方向。问题全出在执行密度上。

**最大的三个短板**：

1. **怪物没有剪影身份**（`px_creature` 只有一张"带俩眼睛的圆球"贴图，6 种怪全靠 tint+缩放区分，main.rs:575-589）。且**巨魔 vs 哥布林都是绿色，只靠体型 1.35× vs 0.98× 区分**——而巨魔是会回血的危险怪。这是 roguelike 的命门级可读性缺陷。
2. **受击/攻击反馈几乎为零**：无闪白、无顿帧、无近战挥击位移（撞击攻击时玩家 `pos` 根本不变，world.rs:279-285）、无死亡动画（sprite 直接 despawn）。战斗只有一团 burst 飘出来，"打到了"的手感缺失。
3. **UI 是纯文字、默认字体、无血条**：HP/法力是文本 `HP {}/{}` 而非血条（spawn_ui main.rs:1011-1029，全项目没有任何 bar sprite），叠加 Bevy 默认无衬线字体与像素贴图的风格冲突，信息层级扁平。

## 维度 1：可读性【命门】

### 1.1 地板 vs 墙 明度对比偏低【中等｜需截图】
- 地板 `px_floor` = `[26,28,40]`（main.rs:1192），杂点 `[34,37,52]`
- 墙体 `px_wall` 主体 = `[52,56,84]`，顶部高光 `[80,86,120]`，底部阴影 `[32,35,54]`（main.rs:1202-1224）

WCAG 相对亮度对比度：**地板 vs 墙主体 = 1.48:1**（极低）；地板 vs 墙顶部高光 = 2.37:1；墙主体 vs 墙高光 = 1.60:1。墙和地板主体明度太接近，**地牢几何主要靠墙顶那道 3px 高光条区分**。建议把墙主体提亮或加冷暖分离（墙偏灰、地板偏蓝），把对比度拉到至少 3:1。

### 1.2 怪物剪影零差异【严重】
`px_creature`（main.rs:1239-1251）只有一个圆盘 + 两只黑眼睛。`actor_sprite`（main.rs:575-589）里 6 种怪全部复用这张贴图，只改 tint 和 scale：

```
troll  'T' 绿[0.45,0.72,0.42] ×1.35
goblin 'g' 绿[0.52,0.85,0.42] ×0.98   ← 和 troll 同色相
ogre   'O' 红[0.95,0.42,0.36] ×1.30
wraith 'w' 蓝[0.76,0.83,0.98] ×1.00
bat    'b' 紫[0.64,0.5,0.74]  ×0.72
rat    'r' 棕[0.74,0.58,0.45] ×0.78
```

蝙蝠没有翅膀、亡灵没有拖尾、老鼠没有尾巴——全是一个圆球。玩家只能靠"颜色+大小"识别怪物。

### 1.3 巨魔/哥布林撞色【严重】
troll `[0.45,0.72,0.42]` 与 goblin `[0.52,0.85,0.42]` 同一绿色相，亮度对比仅 **1.38:1**，唯一区分是体型。多怪同屏叠粒子时极易误判，而**误把巨魔当哥布林 = 送命**（巨魔每回合回血）。建议巨魔压暗偏沼绿或给独立剪影。

### 1.4 玩家可读性 OK【轻微】
玩家袍 vs 地板 = **4.10:1**，怪物 vs 地板约 **6.6:1**——角色对背景的图地关系是好的；问题在"角色 vs 角色"。

### 1.5 无血条、状态无色彩编码【中等】
顶栏（main.rs:1017-1028）把 Depth/HP/Mana/Kills/Score/Turn 全塞进同字号同色一行文本，没有血条/法力条，HP 不标红、法力不标蓝。战斗中无法一瞥读态。（注意：代码里没有任何 bar sprite——README 的面板描述容易让人以为有。）

### 1.6 符文面板列对齐依赖字体【中等｜需截图】
面板用 `format!("[{key}] {:<9} {cat}\n")`（main.rs:1040）靠空格对齐，但全项目未加载任何字体（main.rs:947/962 的 `TextFont` 未设 `font`）。若 Bevy 默认字体是比例字体，列会错乱。

### 1.7 结算卡无遮罩【中等｜需截图】
"YOU DIED / VICTORY!"（main.rs:1108-1129）以 z=50 直接浮在亮着的战场上，无半透明压暗层。加一层 60-70% 黑 scrim 即可。

### 1.8 法术会否糊住战场【轻微，倾向不糊】
单次 burst 6-9 颗、生命周期 0.26-0.7s，不会长期遮挡。Beam 沿整行最多 40 个 streak 亮 0.3s——那正是光束该有的样子。需截图复核 Nova+Spread+Amplify 峰值帧。

## 维度 2：美术方向一致性

### 2.1 半成品，但方向真实
- **成立**：冷调环境（bg `[8,8,13]` 近黑 + 蓝灰地牢）+ 珠宝色元素高光，经典可读的地牢美学；每个元素一色贯穿（gem/投射物/burst/UI 同色）——专业。
- **占位**：怪物一个球、relic 一个星、墙地噪点简单。

### 2.2 全局色板清单
**环境（冷）**：bg`[8,8,13]`、地板`[26,28,40]`、墙`[52,56,84]`、楼梯金`[214,182,86]`。
**元素（珠宝色，runes.rs:127-141 / :197-208）**：火`[255,120,60]`、霜`[120,200,255]`、电`[255,230,90]`、治`[120,255,150]`、力`[220,160,255]`、汲`[210,70,160]`、传送`[150,230,255]`、屏障`[140,175,230]`、Form 蓝`[130,180,255]`、Modifier 灰`[205,205,205]`。

**较弱**：力用紫——"力/冲击"用紫违反直觉（紫通常=魔法/奥术）；屏障是板岩蓝，但"石墙"更该偏灰/褐。

### 2.3 脏色/冲突色
- **屏障复用楼梯贴图【中等】**：`is_temp_wall` 瓦片直接 `tiles.stairs.clone()` 染蓝（main.rs:449-453），金色台阶图案染蓝 ≠ 石墙。应给屏障独立贴图（可用 `px_shard` 思路做块状冰晶墙）。
- **两处元素色不同源【轻微】**：`element.color()`（runes.rs:197）与 `elem_burst` 的 `base`（main.rs:734-748）略有出入（火 `[255,120,60]` vs `[255,140,50]` 等），同一发火球首尾微跳色。建议单一数据源。
- **金色撞用途【轻微】**：楼梯金与 relic 金相近，靠形状区分，同屏时留意。
- **relic 永远金色不染色【轻微】**：`px_relic` 恒为金星（main.rs:505-513 不 tint），玩家无法从地面图标区分 relic 种类。

### 2.4 UI 字体与像素风冲突【中等】
crisp nearest 像素贴图 + Bevy 默认抗锯齿无衬线字体 = 风格割裂。应上位图/像素字体。这是一致性上最容易见效的修正。

## 维度 4：粒子系统品质（elem_burst，main.rs:730-748）

- **火【成立】**：count 9、`accel_y +40` 上升、scale 0.55→0.12 收缩 → 上升余烬。速度 26 偏小可 +10。
- **霜【成立，最好之一】**：shard、speed 44、`accel_y -70` 下落、spin 6 → 冰晶炸开旋转坠落。
- **电【基本成立，有硬伤】**：短促快速，但 **streak 未按速度方向旋转**（Beam 有 `Quat::from_rotation_z`，main.rs:922；burst 里没有）——放射电痕变成乱飞横杠。应按 `vel.to_angle()` 旋转。【中等】
- **治【成立】**：life 0.7 最长、speed 18 慢、缓升 → 温柔上浮。
- **传送【成立，点子好】**：3 个 ring、scale 1.3→0.1 内爆、spin → 环收缩=被吸走。
- **屏障【基本成立】**：shard 下落、不缩放 → 石片砸落定形；颜色偏蓝不够"石"。
- **力【平庸】**：紫色对称放射 puff，无"推"的方向性。应是朝命中方向的定向锥形喷射。
- **汲【平庸】**：品红对称 puff。语义该是 motes 从目标飞向施法者（虹吸），现在丢了"吸向我"的读感。

**系统级通病【中等】**：`spawn_element_burst`（main.rs:752-791）一律对称全向放射——Bolt 命中该顺飞行方向溅射、Force 该定向推、Drain 该向施法者收束。给 `Burst` 加"方向偏置 + 角度锥"参数，三者立刻立体。

## 维度 5：音频规划（当前为零）

事件缓冲 `fx`/`cast_fx` 已是天然音频挂点——在 `spawn_fx`/`spawn_cast_fx` 里 `commands.spawn(AudioPlayer(...))` 即可，几乎零重构。

**最小可行 SFX 集（~14 个）**：移动脚步、近战 thud、敌受击、敌死亡、玩家受伤；通用 cast whoosh + 按元素 5-6 个命中音（烧/碎冰/噼啪/chime/warp/石落）；拾取 chime、下楼 rumble；UI：符文入列 click、报错 buzz、backfire 警告不祥低音。

**风格**：8-bit/chiptune 程序化音效（jsfxr / Bfxr / rfxgen，CC0）。更妙：用 Rust 的 `sfxr`/`usfx` crate **运行时程序化生成音效**，延续"无外部资源"哲学——美术程序化，音频也程序化。

**BGM**：建议要但低于 SFX 优先级。一段低沉 ambient drone 循环对沉浸感 ROI 极高。免费方向：Kenney 音频包（CC0）、Freesound CC0、`bevy_kira_audio` 播 CC0 ambient。

## 维度 6：美术管线建议

**决策点**：程序化贴图在原型期非常优雅，且粒子/FX 层是它的绝对主场；天花板卡在**角色差异化**——无法用 disc/矩形数学优雅手搓 6 个可辨识的 16×16 生物剪影。

**推荐路线：混合制（Hybrid）**
1. FX/粒子继续深耕程序化（保留 elem_burst/spawn_cast_fx/px_spark/ring/shard/streak，这是差异化优势）。
2. ~10 张静态 sprite 换真实像素美术（floor/wall/stairs/player/6 怪/gem/relic/barrier）：README 已铺好切换路径（`asset_server.load` + `TextureAtlasLayout`），改动量低-中。

**推荐资源（许可友好）**：Kenney "Tiny Dungeon" / "1-Bit Pack"（CC0, 16×16，首选）；0x72 "Dungeon Tileset II"（CC0，带怪物动画帧，直接解决剪影）；DawnLike（CC-BY 需署名）；Oryx（付费，roguelike 事实标准）。

**像素纯洁性隐患【中等｜需截图】**：源贴图 16px、`custom_size` 却是 `TILE=18`（main.rs:473）→ 1.125 非整数缩放，nearest 下像素大小不均产生 shimmer；怪物 ×1.35=24.3px 更碎；叠加 glide 亚像素插值（main.rs:597）→ 移动时像素抖动/发糊。要么整数缩放（16→32px）+ 像素网格 snap，要么明确接受柔化。

## 美术视角改进优先级

### P0（低成本、高感知）
1. 受击闪白（sprite.color 瞬白 0.1s tween 回）
2. 近战 lunge（攻击者朝目标 ~30% 格距冲一下弹回）
3. 巨魔/哥布林拆色 + relic 不再撞金（main.rs:576/579 两个 tuple）
4. 加血条/法力条（染色矩形 sprite）
5. 命中敌人时也轻震屏（main.rs:413 附近加一路）
6. 结算卡加半透明黑 scrim

### P1（补齐身份与氛围）
7. 6 个怪物换独立剪影（Kenney/0x72 CC0 atlas，或至少手搓蝙蝠加翅、亡灵加拖尾）
8. 死亡动画：despawn 前 0.2s 淡出/下沉
9. 待机呼吸：±3% 正弦缩放/1px 微动
10. Force 定向喷射 / Drain 虹吸 / Lightning streak 按速度旋转（粒子加方向偏置参数）
11. 接入最小 SFX 集（jsfxr/CC0，挂现有 fx 事件）
12. UI 换像素/位图字体

### P2（打磨与长线）
13. 环境氛围：火把光晕、浮尘、可选雾
14. 下层转场淡入淡出 + ambient BGM
15. 屏障独立贴图、relic 按类型染色
16. 像素纯洁性决策：整数缩放+snap 或明确柔化风
17. 标题画面动态元素（漂浮符文/背景粒子）

**待真机截图验证清单**：墙地对比度实际观感、非整数缩放抖动程度、默认字体是否等宽（面板对齐）、结算卡被背景干扰程度、Nova+Spread 峰值帧遮挡。
